PureComponent
-Pure Components in React are the components which do not re-renders when the value of state and props has been updated with the same values.
-handles the shouldComponentUpdate method itself, does a shallow comparison on both props and state.
-Preferred  to use when the compoent re-rendering depends only on its state and props, not matter the parent props change.
-Normal comp re-renders every time when its parent re-renders, Pure Comp only re-renders wen its props or state changes.
works like -> returns (!ShallowComparison(oldProps,NewProps) || !ShallowComparison(oldState,NewState))

Controlled vs Uncontrolled Components
-Controlled	:	Takes current value through props and notifies changes through callbacks like onChange
				Form element whose value is controlled by React.
				Every state mutation will have an associated handler fns / Callback fns.
				Helps to modify or validate user input.
-Uncontrolled :	Form elements controlled by DOM
				Updation/changing is not controlled, only after submit
				Stores its own state internally, and you query the DOM using a ref to find its current value when you need it.
				This is a bit more like traditional HTML

Virtual-DOM vs Dirty checking
-Dirty Check : Dirty checking slower than observables
			   Pull data at a regular interval and check all of the values in the data structure recursively.
-Virtual DOM : Observable to check if the state has changed is an efficient way to prevent unnecessary re-renders.

			useEffect(() => { }, []); empty [] for mount phase, to run it only once

			useEffect(() => { return ()=>{ dummyFn(); } }, []); dummyFn() will be called before unMounting
			useEffect(() => { return ()=>{ dummyFn(); } }, [variable]); dummyFn() will be called before updating the UI coz of variable
			useEffect(() => { return ()=>{ dummyFn(); } }); dummyFn() will be called before updating for all UI changes

Redux
-Is a predictable state container for JavaScript apps. (Actions,Reducer,Store)
-createStore(x) : x is the Reducer
-ACTION :	App dispatches actions to update the state with/without payloads.
			store.dispatch()
-REDUCER: 	Reducer returns a fresh instance of the state
			Specify how the application’s state changes in response to actions sent to the store
			Takes 2 arguments : State & Action
-STORE	:	Store notifies the app and re-render accordingly.
			Allows access to state via getState()
			Allows state to be updated via dispatch(action)
			Registers listeners via subscribe(listener)
-Alternative of Redux : MobX(new), RxJS (Reactive Extensions for JavaScript)
-Built in PubSub pattern

**Redux in React 4 steps**
	create a reducer
		const combineReducer = combineReducers({rA: reducerA,rB: reducerB});   //multiple reducers
	create a store
		const store = createStore(combineReducer, preloadedState,applyMiddleware(middleware));
	Wrap the app within the Provider from redux	
		<Provider store={store}><App /></Provider>
	Connect the compoent to redux using connect() HOC
		Container = connect(mapStateToProps, mapDispatchToProps)(Component);	

**Middleware**
const store = createStore(reducer, applyMiddleware(thunk));

Closures
  created when a function returns a new function-> (function bundled with its lexcial scope ) is called closure
  a closure provides access to the outer scope from the function’s inner scope.
  A closure controls what is and what is not in the scope of a certain function
  multiple closures of the same function has separate persistent memories
  **Usage**
  -event handlers, callbacks, currying, promises
  -memoization
  -object data privacy
  -throttle and debounce functionality
  **Not to be used**
  -closures in loops
  -Stale Closures in react UseEffect

Fn Currying
  Currying is a technique of transforming a function with multiple arguments, into sequence of nesting functions with single argument at a time.
  In other words, when a function, instead of taking all arguments at one time, takes the first one and return a new function that takes the other args
  **Practical Use**
  -to create utility functions eg logging func(date,type,msg) -> user doesn't have to bother about passing date and type
    create different curried fns for error, warn, info : func(date,type,msg) -> logError(msg) or logInfo(msg)

shims vs polyfills
	Shims intercept API calls and create an abstract layer between the caller and the target. Typically shims are used for backward compatibility. 
	Polyfill is about implementing missing features in an API, whereas a shim wouldn’t necessarily be as much about implementing missing features as it is about correcting features
	So while shims are used for covering up old sins, polyfills are used for bringing future enhancements back in time

Events (3 pahses)
    Capturing phase – the event goes down to the element.
    Target phase – the event reached the target element.
    Bubbling phase – the event bubbles up from the element.
    There are two possible values of the capture options : 
        If it’s false (default), then the handler is set on the bubbling phase. : ele.addEventListener("click", e => alert());
        If it’s true, then the handler is set on the capturing phase.           : ele.addEventListener("click", e => alert(), true);

    Bubbling : events triggered : child->parent->ancestors
    stopPropagation  : stop Bubbling of upper scope
    stopImmediatePropagation  : stop Bubbling of current element if same el has many event handlers 
    preventDefault : prevents the default actions of the browser evenets (mouse, keyboard, form, css, dom) and 
    wants some custom things to happen (validations on text fields, UPPERCASES not allowed, onclick of a checkbox)

Proxy object 
  enables you to create a proxy for another object, which can intercept and redefine fundamental operations for that object.
eg :
      const target = {
        message1: "hello",
        message2: "everyone"
      };

      const handler = {
        get: function (target, prop, receiver) {
          if (prop === "message2") {
            return "world";
          }
          return Reflect.get(...arguments);
        },
      };

      const proxy = new Proxy(target, handler);

      console.log(proxy.message1); // hello
      console.log(proxy.message2); // world
